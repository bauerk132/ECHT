1. **Target**: The O(N^2) conflict detection algorithms in `index.html` (`getOvenConflictIds`, `hasOvenConflict`, and `hasScheduleConflict`).
2. **Current state**: These algorithms iterate over all pairs of blocks, resulting in an O(N^2) time complexity. This causes performance issues when there are many tasks/blocks.
3. **Proposed change**: Optimize by sorting the elements by `day` and then by `startSlot`. With this sorted array, the inner loop can short-circuit (`break`) as soon as the `next` block's day differs from the current block, or its `startSlot` is greater than or equal to the current block's `endSlot`. This drastically cuts down the number of inner loop iterations.
4. **Verification**: I have set up a benchmark (`benchmark_final.js`) which demonstrates that in the worst case scenario (no overlaps, many blocks), the new algorithm completes in ~3ms compared to ~223ms for `getOvenConflictIdsOld`, ~2.7ms vs ~123ms for `hasOvenConflictOld`, and ~3.4ms vs ~124ms for `hasScheduleConflictOld`.
5. **Code Changes**: Update `getOvenConflictIds()`, `hasOvenConflict()`, and `hasScheduleConflict()` in `index.html` to use the optimized sorting-with-early-break method.
